# Secure Document Viewer

The Gateway document viewer is the standard presentation boundary for privately stored PDFs, JPEGs, and PNGs. It consists of the shared `document-viewer.php` component and `document-viewer.js` controller. A page renders the component once and supplies escaped trigger attributes containing a title, safe display filename, authoritative detected MIME type, accessible description, and same-origin Gateway view and download routes. Triggers must never contain provider URLs, buckets, object keys, credentials, numeric database IDs, or client authorization decisions.

Each integrating module owns its authorized routes. View and download requests must independently authenticate the user, resolve current business access, verify the document relationship and active state, restrict MIME to `application/pdf`, `image/jpeg`, or `image/png`, and stream through Gateway private storage. The inline route uses `Content-Disposition: inline`; download uses `attachment`. Both use authoritative metadata, a sanitized filename, `Content-Length`, `Cache-Control: private, no-store`, `Pragma: no-cache`, `nosniff`, `Cross-Origin-Resource-Policy: same-origin`, and a response-specific CSP with `frame-ancestors 'self'`. External framing is not permitted.

PDFs use a same-origin iframe and the browser's native renderer. JPEG and PNG documents use a responsive, centered image. Loading, unsupported-type, and display-failure states retain authorized Open in New Tab and Download fallbacks. Opening the semantic modal moves focus into it, makes background regions inert, locks page scrolling, traps focus, and retains the original scroll position. Closing, including with Escape, clears all sources and restores focus to the trigger. Without JavaScript, the trigger remains a normal authorized inline-view link.

The current PHP/provider stream does not implement HTTP byte ranges. Expected receipt PDFs render through sequential streaming, but large-document seeking may be less efficient; complete, adapter-aware Range support is a recommended future improvement. No partial Range parser should be added at the controller layer.

Future renovation, appliance, HVAC, RM correction, supply-order, application, company PDF, and image modules should reuse the component contract and provide their own independently authorized routes. Automated tests must use fake storage. Manual Wasabi acceptance remains limited to the configured `credit-card-receipts/test/` prefix and must verify embedded viewing, new-tab viewing, download, focus restoration, mobile use, access revocation, and absence of provider details. Real objects are never cleaned up automatically.
