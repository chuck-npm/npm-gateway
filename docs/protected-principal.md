# Protected principal continuity control

Gateway can protect one administrator from lockout through ordinary application operations. Configure `PROTECTED_PRINCIPAL_USER_PUBLIC_ID`, `PROTECTED_PRINCIPAL_EMPLOYEE_PUBLIC_ID`, and `PROTECTED_PRINCIPAL_REQUIRED_CATEGORIES=admin` in the deployment `.env`; never commit the values. Obtain both public IDs through authorized read-only database inspection. Public IDs are validated as ULID-style identifiers and Gateway never falls back to a name, email, numeric ID, class, or current membership.

The `admin` category is the minimum baseline and is sufficient for Corporate Access and Property Access administration under the current authorization rules. Other categories and all Property Access grants remain editable. The Category Access transaction rejects the complete matrix if it would remove a required membership, audits a sanitized denial, and checks again after starting the transaction. The UI badge and disabled checkbox are explanatory only; server enforcement is authoritative.

Run `php bin/gateway protected-principal:check` to inspect user status, employee linkage/status, username validity, and required memberships. `php bin/gateway protected-principal:repair --confirm` connects with the migration profile, previews its exact actions, locks and revalidates the configured identity, and transactionally restores only active statuses and missing required categories. It refuses missing or conflicting identities, preserves unrelated memberships and Property Access, never changes a password, and never runs through HTTP or startup. No automatic startup mutation occurs.

This protection does not defend against direct database access, server access, migration credentials, or compromised application code. Production server, database-administrator and migration credentials must remain restricted. Backups, source control, and audit monitoring remain required. A future database-enforcement phase may add critical invariants if the threat model expands.
